# LAN Scan Gun

[English](README.md)

> 将手机变成 Windows 或 Mac 电脑的无线条码扫描枪。

LAN Scan Gun 是一个“Windows / macOS 桌面端 + 手机网页扫码页”的局域网扫码工具。手机识别条码或二维码后，经局域网发送到电脑，通过系统原生键盘事件写入当前获得焦点的软件。两端均支持 Unicode 文本、可选回车、顺序输入和失败回执。

## 功能

- 手机摄像头扫描条码和二维码
- 通过带配对令牌校验的 WSS 局域网传输
- 不占用、不修改剪贴板，直接输入到当前激活的 Windows 或 macOS 软件
- 可选扫码后自动追加回车
- 手机端支持手动输入发送
- 支持切换镜头、暂停/继续扫码；兼容的设备支持手电筒
- 电脑端和手机端保留最近扫码记录
- 支持回执、顺序输入、重复请求保护和断线重连
- 使用二维码和临时配对令牌连接手机
- 自动生成本地 CA 证书，为手机摄像头提供 HTTPS 环境
- 多网卡电脑可选择手机实际访问的网络地址
- 扫码服务端口和连接页端口可配置并持久化

## 工作方式

```text
手机摄像头
    |  HTTPS + WebSocket
    v
Windows / macOS 上的 LAN Scan Gun
    |  Windows SendInput / macOS CGEvent
    v
当前获得焦点的桌面软件
```

电脑端默认启动两个服务：

| 服务 | 默认端口 | 用途 |
| --- | ---: | --- |
| HTTPS / WSS 扫码服务 | `8787` | 手机扫码页与扫码消息 |
| HTTP 连接页 | `8788` | 证书安装和配对入口 |

两个端口必须不同，可在桌面程序中修改。扫码页面必须使用受信任的 HTTPS 地址，普通 HTTP 页面无法调用手机摄像头。

## 用户快速开始

### 1. 启动桌面程序

使用 Windows 安装包，或在源码目录双击 `Start-Windows.cmd`。从源码启动需要 Node.js 22.12 或更高版本。

macOS：打开 DMG，将 `LAN Scan Gun.app` 拖入“应用程序”并启动。首次使用时，在桌面端“输入设置”中点击辅助功能设置按钮，在“系统设置 > 隐私与安全性 > 辅助功能”中启用 LAN Scan Gun，然后重启程序。源码运行时授权项可能显示为 Electron 或 `input-macos`；请授权当前实际运行的程序。未授权时扫描会返回失败，不会显示输入成功。

### 2. 连接手机和电脑

1. 让手机和电脑连接到同一个 Wi-Fi 或有线局域网。
2. 在桌面程序中选择手机能够访问的网络地址。
3. 使用手机 Safari 或 Chrome 扫描桌面程序显示的二维码。
4. 在连接页核对手机显示的证书指纹与电脑端指纹是否一致。
5. 下载并安装电脑生成的本地 CA 证书。

### 3. 信任证书

- **iPhone / iPad：**安装下载的描述文件，然后进入“设置 > 通用 > 关于本机 > 证书信任设置”，启用对该证书的完全信任。
- **Android：**在系统设置中搜索“安装证书”，选择下载的 CA 证书安装。不同品牌的菜单名称可能不同。

### 4. 开始扫码

1. 在连接页点击“打开扫码页”。
2. 点击“开启摄像头”，允许浏览器使用相机。
3. 在电脑端设置是否追加回车。
4. 切换到目标软件，并将光标放到录入位置。
5. 对准条码或二维码扫码。

手机端只有收到电脑输入回执后才显示成功。超时或断线时不会自动重复发送，以降低重复录入风险。

## 安装与开发

### 环境要求

- Windows 10/11 x64，或 macOS（Apple Silicon / Intel）
- Node.js 22.12 或更高版本，用于源码开发
- Windows PowerShell 5.1，受支持的 Windows 系统自带
- macOS 需要辅助功能授权；源码构建需要 Xcode Command Line Tools（`xcode-select --install`）
- 手机和电脑位于同一局域网

安装包运行时不需要 Node.js，macOS 安装包也不需要 Swift 编译器或 Xcode。

### 从源码启动

```powershell
npm ci
npm test
npm start
```

`npm start` 和 `npm run dev` 会先构建前端资源，再启动 Electron。

在 Windows 上也可以直接双击：

- `Start-Windows.cmd`：必要时安装依赖并启动程序
- `Build-Windows.cmd`：安装依赖、运行测试并生成安装包

### 打包 Windows 安装包

```powershell
npm run dist
```

NSIS 安装包输出到 `outputs/windows/`。建议在 Windows 上执行打包。默认未进行代码签名，公开分发前请自行签名并完成 Windows 实机验收。

### 在 macOS 启动与打包

```bash
npm ci
npm run build
npm test
npm start
```

构建时会自动编译包含 Apple Silicon 和 Intel 的原生输入程序。安装包直接使用随包分发的程序，不会在运行时调用编译器，也不会用剪贴板粘贴。

```bash
npm run dist:mac
```

两种架构的 DMG 输出到 `outputs/macos/`。请在 Mac 上打包；默认未配置开发者签名和公证，公开分发前应配置 Apple Developer 签名、公证并完成实机验收。GitHub Actions 提供独立的 Windows 和 macOS 构建流程。

### 在浏览器预览界面

```bash
npm run build
npm run preview
```

打开 `https://127.0.0.1:8787/index.html`。预览模式仅用于界面和服务测试，不能向操作系统当前光标输入文字。

## 端口设置

桌面程序提供两个端口输入框：

- **扫码服务（HTTPS/WSS）：**默认 `8787`
- **连接页（HTTP）：**默认 `8788`

输入 `1` 到 `65535` 之间的两个不同整数并应用。服务会立即切换，重启后仍会使用保存的端口。

修改端口后：

1. 在手机上重新扫描更新后的二维码。
2. 在系统防火墙中允许局域网访问新端口；macOS 上允许 LAN Scan Gun 接受传入连接。
3. 不要将端口暴露到公网，也不要配置路由器端口映射。

如果新端口已被占用，程序会保留原服务并显示错误。只修改连接页端口时，已经在线的扫码设备不会断开。

## 安全与限制

- 二维码包含配对令牌，应视为临时密码，不要分享给不可信设备。
- 本地 CA 证书由当前电脑生成，保存在 Electron 用户数据目录中，有效期为 180 天；本机 IP 地址变化时也可能重新生成。
- 只安装和信任自己电脑生成的证书，不再使用时请从手机中删除。
- 发送扫码结果时，目标软件必须处于激活状态。
- Windows：普通权限程序不能向管理员权限窗口注入输入，请让两个程序使用兼容的权限级别。
- macOS：必须授权辅助功能；密码框及系统安全输入模式不支持录入。切换激活软件或按住修饰键时会停止输入；部分录入后失败时先核对目标内容再重试。
- 安全桌面、部分游戏和特殊输入控件可能拒绝模拟的 Unicode 键盘事件。
- 含控制字符的扫码内容会被拒绝，最大长度为 4096 个字符；首尾空格会保留。
- “输入成功”只表示输入事件已提交给系统，不代表目标业务软件已经接收或保存数据。

## 常见问题

### 无法启动摄像头

1. 使用独立的 Safari 或 Chrome 打开扫码页，不要使用其他应用内置的 WebView。
2. 检查手机系统和当前 HTTPS 站点是否都允许浏览器使用相机。
3. 确认本地证书已安装并被完全信任。
4. 关闭其他可能占用摄像头的应用。
5. 更新桌面程序后刷新手机页面。
6. 查看手机页面底部的“相机诊断”信息。

### 手机无法连接

- 确认手机和电脑在同一个局域网。
- 确认电脑端选择的网络地址能被手机访问。
- 重启程序或修改端口后，重新扫描电脑端二维码。
- 检查系统防火墙是否放行实际使用的扫码服务端口和连接页端口。
- 确认手机信任的证书指纹与电脑端显示的一致。

### 没有输入到目标软件

- 扫码前先激活目标窗口并放置光标。
- 先用普通权限的文本编辑器测试。
- Windows 扫码时不要按住 `Ctrl`、`Alt`、`Shift` 或 Windows 键；macOS 不要按住 `Control`、`Option`、`Shift`、`Command` 或 `Fn`。
- macOS 检查桌面端“辅助功能”状态；授权或更新程序后重启，且不要在密码框或安全输入模式下测试。
- 检查电脑端历史记录和手机端回执状态。
- 如果发送超时，先核对目标软件内容，再手动重新扫码；程序不会自动重发。

## 项目结构

```text
electron/              Electron 主进程、局域网服务、Windows / macOS 输入
src/renderer/          桌面端和手机端前端源码
tests/                 Node.js 测试
dist/                  前端构建产物
Start-Windows.cmd      Windows 源码启动脚本
Build-Windows.cmd      Windows 测试与安装包构建脚本
LICENSE                MIT 许可证
```

`dist/`、`work/`、`node_modules/`、`electron/bin/` 和生成的安装包属于构建产物，默认不会提交到 Git。
